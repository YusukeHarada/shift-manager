# シフト管理アプリ 設計書

## 1. 概要

### 目的

介護士が紙で配布される月次勤務表を、スマートフォンで手軽に管理・確認できるようにするWebアプリケーション。

### 対象ユーザー

個人用途（ユーザ名はアプリ内で設定）

### 動作環境

- デプロイ先: Vercel（無料プラン）
- 対象ブラウザ: iOS Safari / Android Chrome
- データ永続化: Supabase（PostgreSQL）

---

## 2. 機能仕様

### 2.1 実装済み機能

#### シフト入力

日付をタップするとシフト選択ポップアップが表示される。ベースシフトを1つ選び、αオプションを複数選択して保存する2段構成。

**ベースシフト（7種類）**

| キー | 表示名 | 紙面の記号 |
|------|--------|-----------|
| 日 | 日勤 | 日 |
| 早1 | 早番1 | 早1 |
| 早 | 早番 | 早 |
| 遅 | 遅番 | 遅 |
| 夜 | 夜勤 | 半月記号 |
| 明 | 明け休み | ●（黒丸） |
| 休 | 休み | × |

当直はαオプションにしかない。同じ勤務がベースとαの2箇所から選べて紛らわしかったため、1.5.0 でベースから削除した。

**αオプション（複数選択可）**

| キー | 表示名 |
|------|--------|
| 残 | 残業 |
| 会 | 会議 |
| 当 | 当直 |
| 前休 | AM休 |
| 後休 | PM休 |

「当」は日勤や明け休みの日に当直業務（19:00〜翌7:00）が加わる場合に使う。時刻を持つ唯一のαで、拘束時間と勤務間インターバルの計算に効く。

「前休」「後休」は半休を表すため排他選択（片方を選ぶともう片方が外れる）。ベースシフトと組み合わせて「午前休みで午後から遅番」＝ `遅` ＋ `前休` のように表す。排他制御は `ALPHA_TYPES` の `group: "half"` を見る `toggleAlphaKey()` が担う。

#### カレンダー表示

- 月単位のグリッド形式で表示
- 各セルにベースシフトのバッジを表示
- αオプションがある場合は小さく併記
- 今日の日付をリング（`box-shadow: inset`）でハイライト。枠線は使わない
- 日曜は赤、土曜は青で曜日を色分け

#### リスト表示

- 1日〜月末を縦に並べたリスト形式
- 各行に日付・曜日・シフトバッジ・シフト名・αオプションを表示
- 今日の日付をハイライト

#### 月ナビゲーション

- ‹ / › ボタンで前後の月に移動
- 年をまたいだ移動に対応

#### 集計表示

- 当月のシフト種別ごとの構成比を積み上げバー1本で、件数をチップで表示
- 入力済みのシフト種別のみ表示（0件は非表示）
- 分析タブ表示中は内容が重複するため出さない

#### 次の出勤日表示

- 当月・今日以降で最初の「休み以外」のシフトを表示
- 他の月を表示中は非表示

#### iCal エクスポート

- 当月のシフトデータを `.ics` 形式でダウンロード
- Googleカレンダーへのインポートに対応
- **1日1イベント。** αオプションは `早番（残業・会議）` のように SUMMARY にまとめる
- **UID は日付だけで決まる**（`shift-YYYYMMDD@shift-manager`）。シフト内容を UID に含めると、内容を変えたときに旧予定が残って重複する
- **月内の全日を出力する。** シフト未入力の日は `STATUS:CANCELLED` にして、以前登録された予定を消す

再インポートしても予定が重複しないことを優先した設計。詳細は `src/ical.js` のコメントを参照。

#### 分析タブ

入力済みのシフトから、その月の働き方を数値で振り返る。`analysis.js` の `analyzeMonth()` が集計・疲労度・警告をまとめて返す。

| 表示 | 内容 |
|------|------|
| 今の疲労度 | 今日の値と水準。このあとピークに達する日を予告する（当月表示時のみ） |
| 疲労度の推移 | 日ごとの棒グラフ。持ち越しとその日の勤務に分かれ、タップで内訳を出す |
| 気をつけたい日 | 連勤・勤務間インターバル不足・当直明けの勤務の警告 |
| 今月の勤務 | 稼働日数・休日数・総拘束時間（うち夜勤／うち当直）・1日平均・最大連勤・最短の空き |
| シフト種別の内訳 | 種別ごとの回数と割合 |
| 曜日別の傾向 | 曜日 × シフト種別のヒートマップ |

**疲労度モデルの考え方**

```
f[d] = max(0, f[d-1] × 減衰率 + その日の負荷)
指数 = f を 0〜100 に正規化      ゆとり / 注意 / 要休養 の3水準
```

前日の疲労の一部が翌日に残る蓄積モデル。夜勤の翌日に明け休みを挟んでも疲れが残る実感を表す。負荷はシフト種別ごとに重みを持ち、これに3つの加点が乗る。

| 加点 | 条件 |
|------|------|
| 連勤 | 5連勤目以降、1日ごと |
| インターバル不足 | 勤務間インターバルが11時間未満（労働基準法の努力義務に合わせたしきい値） |
| 当直明けの勤務 | 当直の翌日にそのまま勤務が入る。上2つより軽い |

**重みの具体値と、その値にした根拠は `CLAUDE.md` を正とする。** ここに書くと二重管理になり、片方だけ古くなるため。

**当直の扱い**

当直は泊まりではあるが業務自体は軽く仮眠も取れるため、夜勤とは別物として軽く見る。11時間ルールの判定からも当直の時間帯を外し、「当直明けにそのまま勤務が入る」並びだけを別枠の軽い警告にしている。当直の翌日が休みなら警告しない。

**前月を取りにいく理由**

疲労度は前日からの持ち越しで決まるため、月初を正しく出すには前月末が要る。連勤も月をまたぐ。**分析タブを開いたときだけ**前月を取得し、月ごとにキャッシュする。取得に失敗しても当月の分析は出せるため、エラーバナーは出さずに続行する。

**既知の制限**

先読みは当月内だけ。翌月は取得していないため、月末に近いほど見える範囲が短くなる。

#### 一括入力モード

ボトムナビの「入力」で切り替える。複数の日を選んでから、ベースシフトとαを指定して一括保存する。同じシフトが続く月をまとめて入力するためのモード。

#### 勤務時間表

ボトムナビの「時間表」で開くモーダル。始業・終業を持つシフト（ベース4種＋夜勤＋当直α）の時刻一覧。

#### 表示設定

ボトムナビの「設定」で開くパネル。選択は端末に保存する（localStorage）。

| 設定 | 選択肢 |
|------|--------|
| 週の開始曜日 | 月曜 / 日曜 |
| テーマ | デフォルト / オーシャン / フォレスト / サンセット / モノクローム |
| 表示モード | 自動（OS に追従） / ライト / ダーク |

#### 認証

Supabase 認証（メール／パスワード）。`main.jsx` がセッションを監視し、未ログインなら `Login`、ログイン済みなら `App` を表示する。

## 4. データ設計

### Supabase テーブル定義

```sql
create table shifts (
  id uuid default gen_random_uuid() primary key,
  year integer not null,
  month integer not null,
  day integer not null,
  shift_key text not null default '',
  alpha text[] default '{}',
  created_at timestamp with time zone default now(),
  updated_at timestamp with time zone default now(),
  unique(year, month, day)
);
```

### アプリ内のデータ形式

```javascript
// fetchShifts の戻り値
{
  "1":  { base: "早", alpha: ["残"] },
  "2":  { base: "夜", alpha: [] },
  "3":  { base: "休", alpha: ["会"] },
  ...
}
```

### 環境変数

| 変数名 | 説明 |
|--------|------|
| `VITE_SUPABASE_URL` | SupabaseプロジェクトURL（必須） |
| `VITE_SUPABASE_KEY` | Publishable key（anon key）（必須） |
| `VITE_USER_NAME` | アプリ内に表示するユーザ名（任意・未設定時は `ユーザ`） |

## 6. 状態管理

`App` が持つ主な state。

| state | 型 | 初期値 | 説明 |
|-------|----|--------|------|
| year / month | number | 現在年月 | 表示中の年月 |
| shifts | object | {} | 当月のシフトデータ |
| prevShiftsCache | object | {} | 前月データの月ごとのキャッシュ（分析タブ用） |
| view | string | "calendar" | 表示中のビュー（calendar / list / analysis） |
| picker | number \| null | null | シフト選択ポップアップの対象日（null=非表示） |
| loading / saving | boolean | false | 読み込み中・保存中フラグ |
| error | string \| null | null | エラーメッセージ |
| toast | string \| null | null | 一時表示のメッセージ |
| inputMode | boolean | false | 一括入力モードのオン／オフ |
| selectedDates | Set | 空 | 一括入力で選択中の日 |
| inputShift / inputAlpha | string / array | "" / [] | 一括入力で指定中のシフト |
| showWorkTable / showSettings | boolean | false | モーダルの開閉 |
| direction | number | 1 | 月送りの向き（遷移アニメーション用） |
| weekStart / theme / mode | string | localStorage | 表示設定（端末に保存） |

## 7. データフロー

```
日付タップ
  └─ picker に日付をセット → ShiftPicker 表示
       └─ ベースシフト選択 → αオプション選択 → 保存ボタン
            ├─ shifts を即時更新（楽観的更新）
            ├─ Supabase に upsert
            └─ picker を null → ShiftPicker 非表示

月ナビタップ
  └─ year / month を更新
       └─ useEffect が発火
            └─ Supabase から該当月を取得 → shifts を更新

分析タブに切り替え
  └─ 前月が未取得なら Supabase から取得してキャッシュ
       └─ analyzeMonth(year, month, shifts, prevShifts)
            └─ 集計・疲労度・警告をまとめて受け取り描画
       （取得に失敗しても空データで続行。当月の分析は出せる）

ボトムナビの「出力」
  └─ exportToICal(year, month, shifts)
       └─ .ics ファイルをダウンロード
```

## 9. テスト仕様

### 実施環境

- テストフレームワーク: Vitest（設定は `vite.config.js` に同居）
- レンダリング: @testing-library/react
- DOM環境: jsdom
- モック方式: `src/__mocks__/` ディレクトリによるモジュールモック

### 方針

**計算ロジックは UI を持たない純粋モジュールに切り出し、画面を通さず直接テストする。** `ical.js` と `analysis.js` がこれにあたる。UI を経由すると、計算の誤りなのか描画の誤りなのか切り分けられなくなるため。

件数はテストを足すたびに変わるので本書には書かない。現在の数は `npm test` の出力を見る。

### モック戦略

Supabase と iCal は外部依存のため、テスト時は `__mocks__` ディレクトリのモックに差し替える。これにより実際のDB接続・ファイルダウンロードを行わずにUIの動作を検証できる。

```
vi.mock("../supabase", () => supabaseMock);  // DB接続をモック化
vi.mock("../ical", () => icalMock);          // ファイルダウンロードをモック化
```

`colors.test.js` は `App.jsx` を import するだけでも Supabase クライアントの生成が走るため、色の検証しかしない場合でもモックが要る。

### 各ファイルが担保していること

| ファイル | 担保していること |
|----------|------------------|
| `App.test.jsx` | 画面の描画と操作。ビュー切り替え、月ナビ、シフト入力（単日・一括）、設定の切り替えと永続化、次の出勤カード、月の内訳、勤務時間表、分析タブ（グラフのタップ・前月の遅延取得とキャッシュ・取得失敗時のフォールバック）。保存は `saveShift` の呼び出し引数で検証する |
| `analysis.test.js` | 時刻パース（`翌` 付きを含む）、拘束時間の和集合、勤務間インターバル（負になる場合を含む）、当直と半休の扱い、疲労度の蓄積とクランプ、持ち越しの内訳、連勤カウント、月境界のシード、警告の生成、先読み |
| `colors.test.js` | シフト色のコントラストがライト・ダーク両方で 4.5:1 以上あること、同じ配色が2種類で使われていないこと、ベースシフトの背景の明るさが揃っていること |
| `ical.test.js` | 1日1イベントであること、UID が日付だけで決まること、未入力日が `STATUS:CANCELLED` になること、ファイル名の形式 |
| `Login.test.jsx` | ログイン画面の描画と、認証呼び出しの引数 |
